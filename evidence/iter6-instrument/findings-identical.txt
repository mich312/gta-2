Requirement 1: which findings fire must not change.

Proved on BOTH bakes, not one — the same detector code run against the
iteration-4 bake and the iteration-5 bake, each diffed against what the
iteration-5 detector said about that same bake.

The only edit to a finding line is a new `m=<magnitude>` column between
`severity` and `reason`. Strip it and the lines are byte-identical, in the
same order, including the twelve-line `--limit` truncation lines.

  strip() { sed -E 's/^([^#].{0,200}?)  (m=[0-9]+) {0,8}  /\1  /'; }

Why this holds by construction
--------------------------------------------------------------------------
`mag` is a NEW field. Not one gate, threshold or `rank` expression was
touched, and `rank` is still the sole sort key — so the set of findings, the
order they print in, and which twelve survive `--limit` are all untouched.

The one behavioural edit in the detector is `lanesServingNothing`'s three
gates being lifted into `firesLanes()` verbatim so `--selftest`'s half-fix
control can select by the same rules the detector fires by. Both runs above
are AFTER that refactor, on both bakes, so it is covered by the diffs.

The `x,y,w` field is untouched and still a `mapgen --crop=` argument. Taken
straight off an audit line with awk and fed back in:
